# Upstream

YAL is a port of an existing project. This file says which one, how much of it
there is, and where to read it.

---

## The original project

| | |
|---|---|
| Name | **Tinycast** |
| Author | **Abue Ammar** |
| Repository | <https://github.com/abue-ammar/tinycast> |
| Website | <https://tinycast.dev> |
| Documentation | <https://tinycast.dev/docs> |
| Licence | GNU Affero General Public License v3.0 |
| Platform | macOS (Swift, SwiftUI, AppKit) |

Tinycast is a keyboard launcher for macOS. It is a free and open source
project by Abue Ammar.

YAL is an **unofficial community port**. It is not affiliated with, endorsed
by, or supported by the Tinycast authors, and no part of YAL's work is done
on their behalf.

## The exact upstream revision this port follows

```text
58168bf7e0b721f7c5fbfc7f4e8a068a48cff446
2026-11-08
Revert "Draw the compact bar on the expanded panel's glass (#1845)" (#1846)
```

That commit is recorded in [`upstream-sha.txt`](../upstream-sha.txt) and
[`upstream-commit.txt`](../upstream-commit.txt) in this repository, and it is
the revision the parity ledger was generated from.

The upstream sources are not committed here. To get them:

```powershell
git clone https://github.com/abue-ammar/tinycast upstream
```

The `upstream/` and `upstream-docs/` folders are in `.gitignore`.

The upstream documentation, all 42 pages, is fetched from
`https://tinycast.dev/llms.md/<page>/index.md`. The upstream website publishes
that form of every page so that tools can read them.

## What upstream provides, and what YAL does with it

| Upstream | YAL |
|---|---|
| ~869 Swift files under `Tinycast/Features/<Feature>/` | The behaviour, in Rust, in `crates/` |
| ~127 test files under `Tests/` | The cases, in Rust, as `#[test]` functions |
| `Tinycast/Resources/Localizable.xcstrings` | The nine-language string catalogue, regenerated by `cargo xtask i18n` |
| `Scripts/raycast-runtime/` | The reference for extension compatibility |
| `website/content/docs/` | The 42 pages the parity ledger is generated from |
| `LICENSE` | The AGPL-3.0 text, carried over unchanged |
| `NOTICE.md` | The third-party notices, carried over unchanged |

### The Swift sources are the authority

Where the documentation and the source disagree, the source wins. The
documentation describes what a feature is for; the source says what it
actually does.

That is why the parity ledger is generated from the documentation and then
*checked against* the source as each feature is ported: the documentation
gives the exhaustive list of behaviours, and the tests give the truth.

## The licence

Tinycast is licensed under the **AGPL-3.0**. YAL is a derivative work and is
distributed under the same licence, because that is what the AGPL requires of
a derivative work.

Both copyrights are in [`LICENSE`](../LICENSE):

```text
Copyright (C) 2026 Abue Ammar (Tinycast, the original work)
Copyright (C) 2026 YAL community port contributors (the Windows port)
```

The AGPL's section 13 requires that users of a networked version be able to
get its source. YAL offers the same way: the whole repository is the source
of the whole program, and it is published under the same terms.
